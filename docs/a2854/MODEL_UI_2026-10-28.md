# Model-specific user interface

The Remote gesture animation and the legacy Windows Bluetooth, filter and ESP32
controls remain available in first-generation mode. In A2854 mode the UI hides
them, provides a separate A2854 guide and shows an adapter-list status for
Barrot `33FA:0001`. That status reports only what device enumeration and its
service name establish; it does not assert that the device is healthy or that
the remote is connected. Empty or failed enumeration is shown as uncertain.

The A2854 mapping page explains that TV, Siri and Power are displayed but not
assigned to Windows input actions. The existing routing remains unchanged.
The tray tooltip shows the current status and an available battery percentage;
the battery becomes unknown on A2854 disconnect. The debug-only Windows BLE
scan button is hidden in A2854 mode and the remote's diagnostics are identified.
The guide explains the existing protected bond, explicit Start/Stop, ordinary
wake buttons, input options, saved five-point calibration and tray Quit. It does
not instruct a new pairing or deletion of existing bond data.

Validation: Windows Release solution build, external driver and firmware
downloads disabled, 0 warnings and errors; offline suite 560/560. An offscreen
WPF fixture checked 135 model/visibility transitions across ko/en/fr and widths
1024, 1280 and 1600 DIP and rendered nine A2854 guide images. It used no real
session, no USB controller and no Windows input injection. The fixture checks
visibility, not every binding or the real system tray. Actual window behavior,
tray display, adapter state, BLE and physical remote behavior remain untested.
