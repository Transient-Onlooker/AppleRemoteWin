## 1. 협업 역할 — 새 에이전트가 가장 먼저 읽을 내용

- **ChatGPT(이 대화의 주 에이전트) = 메인 개발자.** GitHub 코드를 직접 확인하고 설계·구현·버그 수정·커밋·푸시·문서화를 책임진다. 구현할 일을 로컬 Codex에 통째로 떠넘기지 않는다.
- **사용자 PC의 로컬 Codex = 독립 검증자/실기기 실행자.** Windows Release 빌드, 테스트, 로그 수집, 재현·정적 검토, 명시적으로 허가된 하드웨어 실험을 수행하고 결과를 ChatGPT에 전달한다. 기본적으로 소스를 수정하거나 커밋하지 않는다(사용자가 따로 역할 변경을 요청한 경우 제외).
- 사용자는 이전에도 위 역할 분담을 명시했다. 다음 ChatGPT 턴에서는 **사용자가 로컬 검증 결과를 전달하면, 발견된 결함은 ChatGPT가 직접 GitHub에서 고치고 테스트를 추가하며 푸시**해야 한다. 새 코드는 로컬 검증 이전에 성공했다고 주장하지 않는다.
- 대화와 과거 문서는 길다. 아래 기술 요약 및 **정확한 소스 파일 경로**, `docs/a2854/GUI_PASSIVE_STARTUP_2026-10-23.md`, `docs/a2854/APP_INTEGRATION_2026-10-23.md`부터 확인한다.

## 2. 안전·하드웨어 제약 — 절대 무시하지 말 것

1. 전용 **외장 Barrot BR8652A12 / Axxen** Bluetooth USB 동글 **`VID:PID 33FA:0001`**을 **USB 3.0 허브**에 연결해 사용. 현재 사용자 환경에서 **WinUSB / `oem86.inf` / PnP Code 0**로 작동하며 실제 A2854 송수신에 성공했다. EP0 HCI 요청 타입 0x21은 이 계열에서 사용된다.
2. **내장 Intel AX200 Bluetooth `8087:0029`는 Windows BTHUSB, Code 0 유지.** 내부 장치 드라이버 바꾸기, 전용 동글과 합치기, PnP 재시작/드라이버 교체/테스트 서명 인증서 조작, 불필요한 Zadig·필터 설치 금지. 기존 Barrot WinUSB도 재설치하지 않는다.
3. **기존 DPAPI 본딩을 보존:** `%LOCALAPPDATA%\AppleRemoteWin\A2854\bond.v1.dpapi`. Windows `CurrentUser` DPAPI 암호화. 기존의 정식 A2854 앱 경로에서는 `ProtectedBondStore`를 읽기만 하며, **재페어링·본드 삭제·평문 JSON 저장으로 폴백하지 않는다.** 실제 LTK/EDIV/RAND, Bluetooth 주소, 원시 SMP 패킷, DPAPI blob은 로그·문서·GitHub에 올리지 않는다.
4. Legacy Just Works는 **MITM 인증 없는 페어링**이며, DPAPI는 **저장 시 키 보호**일 뿐 BLE 무선 인증 강도를 높이는 기술은 아니다. 추가 SMP 재본딩은 **Apple TV와의 기존 페어링을 깨뜨릴 수 있으므로 별도 명시적 승인**이 필수. 이전 본딩은 이미 성공·저장되어 있으니 재본딩할 이유가 없다.
5. **실기기 연결·GATT 쓰기·`0xF0 ← 0xAF` 기능 활성화, Windows `SendInput` 마우스/키보드 제어는 각각 승인된 범위 안에서만 실행**한다. 이번 인수인계 요청 자체는 어떠한 새 하드웨어 실험도 승인하지 않는다.
6. **마이크 Report `0xFA` 구독·수집/녹음 금지.** 현재 명시적 HID allowlist는 버튼 0xFB·터치 0xFC뿐이다. Siri, TV, Power 버튼은 초기 앱 통합에서 Windows 동작을 일으키지 않게 제한했다.
7. 1세대 Siri Remote 지원을 회귀시키지 말 것. 이전 1세대 `SiriRemoteBle`과 평문 `BondStore`는 역사적 경로로 존재하지만 **전용 Barrot `33FA:0001`를 이 1세대 경로에서 열거나 SMP를 자동 수행해서는 안 된다.**
8. 같은 Barrot를 `A2854.Probe`와 WPF 앱 두 프로세스에서 동시에 열지 않는다. **다른 프로세스까지 포괄하는 동글 독점 사용 보장은 아직 개발·검증되지 않았다.**

## 3. 실제로 성공한 실기기 기록 — 사실만

| 단계 | 확인 결과 |
| --- | --- |
| Windows + Barrot WinUSB HCI | 컨트롤러 Reset/Read Local Version, 광고 발견, LE 연결 확인 |
| SMP Legacy Just Works | Pairing Request/Response, Confirm/Random, peer Confirm 확인, STK 암호화, LTK + EDIV + RAND 분배 성공 |
| 보호 본딩 | `--smp-pair-only --confirm-pairing --save-bond`를 **별도 승인 후 한 차례** 실행해 CurrentUser DPAPI 본드 암호화 저장 성공; 기존 Apple TV 본딩 영향 가능성은 고지 |
| 암호화 재연결 | 저장된 LTK/EDIV/RAND로 **SMP 재페어링 없이** HCI Encryption Change 성공 |
| GATT 탐색 | HID service `0x1812`, Report Reference `0x2908` 확인 |
| 실제 값 핸들 | 버튼 `0xFB → 0x0039`, 터치 `0xFC → 0x003D`, Feature `0xF0 → 0x004D` |
| 실측 CCCD 핸들 | 버튼 `0x003A`, 터치 `0x003E` (`0x2902`를 **탐색으로** 확인; 임의 오프셋 추측 아님) |
| 초기 입력 성공 | 버튼 **59프레임**, 터치 **720프레임**, malformed **0**. 다만 리모컨이 `0x13`으로 먼저 끊어져 초기 CLI는 exit 1; 이 시도에서 호스트 CCCD 해제/0x16은 미검증 |
| 최종 승인된 8초 CLI 입력 검사 | 버튼 **33프레임**, 터치 **360프레임**, malformed **0**, 두 CCCD에 `00 00` 해제 **각각 ATT Write Response**, HCI Disconnect Command Status OK, 일치하는 Disconnection Complete **로컬 `0x16`**, **exit 0** |
| 실제 WPF GUI A2854 세션 | **실행·검증한 적 없음** |
| Windows 마우스·미디어 입력 합성 | **실행·검증한 적 없음** |
| 장시간 안정성·원격 종료 `0x13` 원인 | **미확인**. `0x13`은 remote-user terminated라는 분류일 뿐 구체적인 슬립/버튼/절전 원인은 알 수 없음 |

실험 증거: [HID 실기기 로그](a2854/HID_INPUT_HARDWARE_2026-10-23.md), [DPAPI/재연결/GATT](a2854/PROTECTED_BOND_HARDWARE_2026-10-22.md), [SMP 기록](a2854/SMP_NEGOTIATION_2026-10-22.md). 전부 민감 주소·키를 빼고 기록.

## 7. 알려진 위험·자주 틀리는 부분

- **레거시 자동 연결 경로:** 초기 WPF 구현은 단지 앱을 실행했을 때 저장된 A2854 모드가 자동 Start될 위험이 있었다. 현재 소스는 `RemoteStartupPolicy`와 독점 Barrot 분리 코드를 추가했지만 **새 빌드 검증과 수동 GUI 검사 전**이다.
- **기존 `CLAUDE.md`/README/과거 handoff 문서:** 1세대 중심·2026-10-21 기준으로 `Windows A2854 실수신 없음`이라고 써 있는 내용은 **이제 낡은 기록**. 실기기 8초 캡처 성공이 최신 사실이다.
- **마우스 버튼 stuck-state:** Win32 `SendInput`에서 mouse-up을 거부하면 mapper가 held 상태를 보존하고 재시도 및 경고한다. 성공이 반환되지 않는 환경에서 실제 OS 해제까지 보장하지 않는다.
- **종료 경합:** USB 오류·일반 GUI 이벤트 예외·늦은 HID 알림·중단 및 종료 콜백 문제는 여러 차례 수정·모의 테스트되었지만 **앱 런타임/실제 USB 예외 주입으로 검증한 적 없음**.
- **랜덤 주소 모의 테스트 과거 1회 타임아웃:** `SiriRemoteBleTests.Random_address_peer_is_discovered_connected_and_paired_with_correct_smp_address_type`; 이후 제한 시간을 30초로 늘리고 단계 로그를 추가. 3회 모두 통과했으나 근본 원인이 확인된 것은 아니다.
- **민감정보:** 이 파일에는 사용자의 주소, MAC 주소, DPAPI 파일 바이트, 인증서, 키를 기재하지 않았다. 이 원칙을 계속 유지.
