# Siri Remote A2854 → native Windows — 최신 인수인계 (2026-10-21 KST)

> **저장소 통합 완료:** 이전 `siri-remote-for-windows`의 100개 파일을 [`reference/siri-remote-for-windows/`](../reference/siri-remote-for-windows/)로 **Git blob SHA 일치하게 복사**했고, [`docs/a2854/`](a2854/README.md)를 현재 분석·개발 문서의 중심으로 지정했다. 이전 Git 이력은 [원본 저장소](https://github.com/Transient-Onlooker/siri-remote-for-windows)에 그대로 남겨 둔다. 자세한 내용: [통합 기록](a2854/CONSOLIDATION.md).

> **현재 상태: Windows A2854 입력 실수신은 아직 성공하지 못함.**
> 이 문서는 [2026-10-18 통합 인수인계](HANDOFF_2026-10-18_A2854.md)와
> [실험 경과](A2854_PORT_STATUS.md) 이후의 결론을 반영한 **최신 시작점**이다.
> Linux/WSL 실기기 수신 성공과 Windows 구현/테스트 결과를 절대 혼동하지 말 것.

## 1. 목표와 역할

- 목표: Apple Siri Remote **3세대 A2854 (USB-C)**를 Windows 11에서 터치패드 마우스·버튼·미디어 리모컨으로 사용. 최종 사용 시 WSL/Linux/USB/IP 없이 native Windows로 실행.
- 개발: 이 저장소의 `feat/a2854-support` 브랜치 (원본 1세대 앱은 보존). 참고/실측: [siri-remote-for-windows](https://github.com/Transient-Onlooker/siri-remote-for-windows).
- 협업: ChatGPT가 핵심 설계·주요 코드 변경·복잡한 원인 분석과 GitHub 작업을 맡고, 사용자 PC의 로컬 AI 에이전트는 환경 조사, 명령 실행, 하드웨어 측정, 빌드/테스트와 소규모 디버깅을 수행한다. 로컬에서만 확인 가능한 성공을 코드 커밋만으로 주장하지 않는다.

## 2. 확인된 사실 / 아직 확인되지 않은 것

| 분야 | 검증 수준 | 관측 사실 및 한계 |
| --- | --- | --- |
| Linux/WSL2 + Intel AX200 + BlueZ | **실기기 성공** | `0xF0 <- 0xAF` 이후 A2854 버튼 `0xFB`, 터치/호버 `0xFC` 수신. Windows 성공 증거는 아님 |
| Windows 내장 AX200 / BTHUSB | **실기기 진단** | HID GATT `0x1812`는 보이지만 Report 특성 열거 `ACCESS_DENIED`; Siri Remote HIDClass `mshidumdf` 하위 장치는 Code 10 / `0xC00000B9` |
| Windows 빌드 / 단위 테스트 | **실행 결과 확인** | .NET SDK `10.0.402`, **89/89 통과**, 이전 `A2854.Probe` Release 빌드 성공. **아래 최근 BLE 주소 유형 수정 전**의 결과임 |
| A2854 Windows WinUSB 콘솔 | **컨트롤러 미준비** | 직접 HCI 프로브에서 `WinUSB controller unavailable`. 내장 AX200이 정상 `BTHUSB`인 탓으로, BLE 연결/페어링까지 진행하지 못함 |
| HID child 한정 재시작 | **2026-10-19 실기기 실행 / 실패** | 아래와 같이 **관리자 권한으로 단 한 번** 재시작, `pnputil` exit code 0이지만 Code 10 유지 |
| 최근 public/random BLE 주소 유형 개선 | **GitHub 코드·모의 테스트 추가** | `Ble.cs`, `Smp.cs`, `SiriRemoteBle.cs`, `A2854.Probe`, 테스트 수정 완료. **수정 후 Windows 빌드/테스트 결과와 실수신은 아직 미제출** |
| ThinkPad T490s Intel Wireless-AC 9560 | **사용자 제공 하드웨어 정보** | 9560 탑재 사실만 확인. 이 PC에서 A2854 페어링/HID/WinUSB 성공 또는 실패 여부는 아직 **미실험** |
| 외장 USB Bluetooth 동글 | **구매/실물 확인 전** | USB VID/PID, 컨트롤러 제조사, 실제 WinUSB 사용, A2854 수신 모두 미검증 |

### 실제 '마지막 내장 HID 시도' 결과

`tools/A2854.Probe/LastBuiltinHidAttempt.ps1`의 인수 없는 읽기 전용 검사는 대상 1개를 확인했다.
관리자 PowerShell에서만 `-Restart` 1회를 실행했다 (일반 권한 시도는 변경 없이 거부).

```text
Remote anchor candidates: 1
Unique failed HID candidates: 1
Target checks passed: one remote descendant, HIDClass, mshidumdf, Code 10, NTSTATUS 0xC00000B9.
PnP restart exit code: 0
After restart: device status=Error; problem code=10; NTSTATUS=0xC00000B9
HID not recovered (or not proven recovered).
```

Intel AX200은 `BTHUSB` / PnP `OK`, 드라이버 `23.160.0.9`로 유지됐다.
**동일한 재시작을 반복하거나 기존 Gen-1용 커널 필터를 무작정 설치하지 않는다.**
이 결과는 Windows 내장 HID의 단순 PnP 재시작이 실패했다는 뜻이지, 모든 Windows 접근 방식이 불가능하다는 증명은 아니다.

## 3. 최근 코드 변경과 검증해야 할 부분

2026-10-19 다음 구현을 `feat/a2854-support`에 커밋:

- `LePeer(Address, AddressType)`, `ScanPeerAsync(... allowRandom)`: public(0)/random(1) BLE 주소 구분 및 보존.
- `LeCentral.ConnectAsync`: HCI 연결 명령에 스캔된 peer address type 전달.
- `SmpPairing.PairAsync`: legacy SMP confirm `C1` 계산에서 peer address type 사용.
- A2854 진단 콘솔: 회전하는 주소를 새로 스캔하도록 `allowRandomAddress: true` 설정. 원래 1세대 public-only 기본 경로는 유지.
- `SiriRemoteBleTests`: fake random-address peer 연결/legacy SMP 페어링 테스트 추가.
- 관련 코드 변화가 실기기에서 작동한다는 뜻은 아니다. **로컬 Windows에서 `dotnet test` 및 `dotnet build`를 다시 실행해 결과를 확인할 것.**

열려 있는 기술 위험:
1. A2854 광고가 Apple 제조사 데이터 `0x004C`와 HID 서비스 `0x1812`를 한 AD payload에 함께 싣지 않으면 기존 판별 함수에서 누락될 수 있음 (광고/scan response 병합 미지원).
2. Legacy "Just Works" SMP 페어링·LTK 재사용이 A2854의 주소 프라이버시·보안 절차와 완전히 일치하는지 미검증.
3. Windows 외장 컨트롤러의 초기화/펌웨어/확장 스캔과 A2854의 `0x2908` Report Reference·`0xF0` unlock을 실기기에서 단계별 검증해야 함.
4. 정상 raw `0xFB`/`0xFC` 입력 수신 이후에만 `RemotePipeline` 모델 분기, `SendInput`, WPF, 연결 해제 시 held-key release를 통합할 것.

## 4. 외장 동글 후보 조사 (구매 전, 증거와 추정 분리)

| 후보 | 확인된 정보 | A2854/WinUSB 관점 |
| --- | --- | --- |
| **TP-Link UB500의 특정 Realtek 리비전** | 원본 개발자의 [PR #15](https://github.com/AnthoDingo/AppleRemoteWin/pull/15)에서 USB `2357:0604` (Realtek RTL8761B 계열)로 **Gen-1** 실험 기록 | 기존 `RealtekFirmware`와 직접 HCI 코드 활용 후보. **모든 UB500 리비전이나 A2854 성공은 보장하지 않음** |
| **다이소 Bluetooth 5.0 품번 1035660** | [다나와 제품 정보](https://prod.danawa.com/info/?pcode=30126551): Realtek `RTL8761BUV` | Realtek 계열이어서 검토할 가치가 있음. 이 **개별 제품의 USB ID·WinUSB/A2854 실험은 아직 없음** |
| **다이소 Axxen/Pleigo Bluetooth 5.3 (BD20/BD21 계열 여부 확인 필요)** | 5.3 판매/사용 후기는 존재; [액센 지원 공지](https://axxen.co.kr/?act=board&bbs_code=FAQ&bbs_mode=view&bbs_seq=89&page=2)는 BD20/21의 Windows 10/11 무설치 사용 및 구형 Windows용 BRLink 드라이버를 안내 | 칩셋이 `BR8651`이라는 **사용자 보고가 있으나 다이소 판매 개체의 정확한 칩셋·VID/PID는 확정되지 않음**. 기존 Realtek 펌웨어 패치를 그대로 적용하지 말 것 |
| **Barrot/BRTLink 역공학 참고** | [brtusb](https://github.com/zhuzhuzihan/brtusb)는 `33FA:0001`/`33FA:0010` 계열의 Linux HCI(H:2) 수송 및 사유 초기화 분석 | **다이소 5.3 제품이 동일한 USB ID라는 증거가 아니다.** Linux 커널 구현은 Windows/WinUSB/A2854 실수신의 증거가 아님 |

일반 USB **Wi-Fi 전용** 동글은 Bluetooth HCI 컨트롤러를 제공하지 않으므로 대체품이 아니다.
Bluetooth 버전 숫자(5.0 vs 5.3)보다 **실제 칩셋/리비전/VID/PID, HCI endpoint, 초기화 절차**가 중요하다.

참고: Lenovo 공식 [T490s PSREF](https://psref.lenovo.com/syspool/Sys/PDF/ThinkPad/ThinkPad_T490s/ThinkPad_T490s_Spec.html)는 Intel Wireless-AC 9560 탑재 구성을 명시한다. 사용자는 본인 T490s가 **9560**임을 직접 확인했다. 이 기기의 Windows에서 A2854의 HID 동작이 AX200과 다르게 나올 가능성은 있으나, **아직 시도 자체를 하지 않았음**.

> **2026-10-21 실물 구매 업데이트:** 기존 5.0 Realtek 동글은 단종되어 사용자가 **다이소 Axxen Bluetooth 5.3 동글을 구매**했고 칩셋이 **Barrot/BRLink BR8652A12**라고 알려줬다. 과거 BR8651 추정은 구매 개체에 적용되지 않는다. 이 보고는 아직 USB VID/PID·인터페이스·HCI 버전 실측으로 확인한 것이 아니며, WinUSB 및 A2854 동작도 미검증이다. 향후 동글 실험·리서치의 기준은 [BR8652A12 개별 하드웨어 조사](a2854/BARROT_BR8652A12.md)로 업데이트한다. Barrot 과거 문서의 Bluetooth 5.0 표기와 일부 판매·지원 문서의 5.3/LMP12.x 표기는 상충하므로 실제 HCI Read Local Version으로 후속 확인한다.

## 5. 다음 작업 우선순위

1. **로컬 실행 에이전트:** `feat/a2854-support`를 최신화해 `dotnet test tests/AppleRemote.Tests -c Release` 및 `dotnet build tools/A2854.Probe/A2854.Probe.csproj -c Release`. 단순 오류는 수정하고 실제 결과를 전달.
2. **T490s(AC 9560):** 원한다면 별도 PC에서 Windows 페어링/HID PnP를 **읽기 전용 진단**. 실패 시 내장 컨트롤러를 WinUSB로 교체하지 말 것. Linux는 이미 입증된 입력 수신 경로로 참고 가능.
3. **USB 동글 선택:** 실물 구입 뒤 먼저 `Get-PnpDevice`/`Get-PnpDeviceProperty` 및 USB VID/PID/interface/endpoint를 확인하고, 장치 변경 전 복원 절차를 확보. 변경하더라도 **외장 동글에만 WinUSB 바인딩**.
4. **실기기 직접 HCI:** USB 오픈 → 컨트롤러 초기화 → 광고 발견 → 연결 → SMP/bond/encryption → GATT HID `0x2A4D`/`0x2908` → `0xF0 <- 0xAF` → `0xFB`/`0xFC` 원시 수신. 실패한 단계별로 분리 진단.
5. **입력 실수신 이후:** A2854의 마우스·키 매핑 및 네이티브 WPF 앱 통합. 1세대 기능은 유지하며 실측/빌드/단위 테스트/실사용을 구분해 기록.

## 6. 보안·원본 자료

- BLE MAC/주소, 시리얼, 호스트 고유 PnP 경로, 원시 ETL, bond key, 오디오 데이터를 GitHub에 올리지 말 것.
- `%APPDATA%/AppleRemote/a2854-probe-bonds.json`은 민감한 키 저장소. Gen-1의 `bonds.json`과 별도.
- 기본 Bluetooth/Wi-Fi 연결을 유지하기 위해 **Intel AX200 및 T490s의 AC 9560 내장 드라이버는 교체하지 않는다.** 시스템 전역 변경은 사전에 별도 승인·복원 계획을 갖춘다.
- 코드 라이선스: AppleRemoteWin `AGPL-3.0-or-later`, 참고 Linux 포크 `GPL-3.0`.
- 이전 [2026-10-18 인수인계](HANDOFF_2026-10-18_A2854.md)는 당시 시점의 **역사적 기록**이며, 마지막 HID 실험의 미실행 상태와 재시도 안내는 **이 문서의 최신 사실로 대체**한다.
