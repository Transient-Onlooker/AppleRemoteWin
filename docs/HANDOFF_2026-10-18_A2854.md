## 2. 실제 A2854 프로토콜 — 검증된 부분

- 리모컨: Apple Siri Remote 3세대, A2854 USB-C. Apple BLE Manufacturer `0x004C, HID 서비스 `0x1812, Battery `0x180F/`0x2A19, Bond Management `0x181E, Apple 사유 서비스.
- HID `0x2A4D 보고서 특성이 여러 개 존재. 반드시 descriptor `0x2908 (Report Reference: ID, type)로 구분해야 한다.
- 입력 `0xFB: 리포트 ID를 뺀 **2바이트 리틀엔디언 버튼 비트맵**. 주요 비트: `0x0001 TV, `0x0002 Volume Up, `0x0004 Volume Down, `0x0008 Select/Click, `0x0010 Power, `0x0020 Siri, `0x0040 Back, `0x0080 Mute, `0x0100 Play/Pause, `0x0200 Up, `0x0400 Right, `0x0800 Down, `0x1000 Left. 매핑은 원본 Rust `src/decoder.rs 및 포크의 `A2854Decoder.cs 참조.
- 입력 `0xFC: 첫 바이트가 `0x32인 터치 payload. 첫 접점 11바이트/둘째 접점 포함 18바이트(Report ID 제외), tick 카운터, signed 12-bit XY, major/minor, pressure 관련 값, flags/hover/각도. `pressure > 0 은 접촉이나 물리적 힘(N)의 증거가 아님. `hover=true 와 `pressure=1 공존 사례 있음.
- 입력 `0xFA 는 마이크 보고서로 열거·구독만 확인. **오디오 수신 성공·음성인식 성공 아님**. `0x60/`0xFD/`0xFE 등 나머지 Report 의미 미확정.
- 활성화 Feature `0xF0 에 `0xAF 쓰기 후 입력 수신 성공. `0xF1 에 같은 값 쓰기는 ATT `0x82 오류를 봤지만 동작에는 필수인 것으로 확인되지 않음.
- 별도 버전/기기의 GATT attribute handle 번호를 A2854에 하드코딩하지 말 것.
- 실측 fixture 예: `FB 00 04 (Right 누름), `FB 00 00 (해제), `FC 32 14 FC 01 C9 9E FB 51 44 01 66 (hover, x=-311, y=-71), `FC 32 36 FC 00 C9 9E FB 00 00 00 67 (해제).

## 3. Windows 내장 AX200의 근본 문제

물리 장치에 대한 Windows 실측:

1. WinRT `BluetoothLEDevice.FromIdAsync/`0x1812 검색: 페어링 장치 인식, 7개 서비스, 때로 첫 연결 시도 `UNREACHABLE → 재시도 `SUCCESS/CONNECTED.
2. 그러나 HID 서비스의 `0x2A4D 특성 열거: `ACCESS_DENIED. Windows가 소유한 HID-over-GATT 서비스 접근 제한과 부합. 일반 Bleak/WinRT 반복으로 우회된다고 가정하지 말 것.
3. PnP 부모·자식 연관성 조사에서 **해당 DL1/Siri Remote** 하위 `BTHLEDEVICE HIDClass 장치: 서비스 `mshidumdf, Code 10, `ProblemStatus=0xC00000B9 (STATUS_COULD_NOT_INTERPRET), Kernel-PnP Event 411/ HIDCLASS Event 3.
4. HIDCLASS ETW에는 **38바이트 디스크립터** 기록. 분석 기록상 Feature ID `0xB8 의 50비트×6 = 300비트(바이트 정렬 아님), Input ID `0x04 의 Usage 부재 가능성. Linux 실수신 `0xFB/`0xFC 와 ETW `0x04/`0xB8 의 불일치는 추가 검증 필요. **이것들이 Code 10의 실제 원인임은 아직 입증되지 않음.**
5. WPR verbose 시도는 10.38MiB ETL 수집만 확인했으며 정확한 HIDCLASS WPP provider 작동/파서 오류 메시지를 확인하지 못함. 같은 수집을 근거 없이 반복하지 말 것. 격리 VM의 실제 HIDCLASS 파서 비교 또는 새 증거가 있어야 가설을 확정할 수 있다.

2026-10-18 Windows PowerShell 장치 상태:

```text
Intel Wireless Bluetooth (Intel AX200), USB VID:PID 8087:0029
PnP Status      : OK
PnP Class       : Bluetooth
Driver service  : BTHUSB
Driver INF      : oem116.inf
usbipd          : BUSID 1-3, Not shared
```

**정확한 해석:** `UsbHci.Open()은 일반 Bluetooth 장치를 찾는 코드가 아니라 **WinUSB로 열린 USB HCI 컨트롤러**를 찾는다. AX200은 정상적으로 `BTHUSB 에 바인딩되어 있으므로 발견되지 않는다. `usbipd Not shared 는 단지 WSL USB/IP로 공유되지 않음을 의미하며 WinUSB 접근 허가와 무관하다. 추가 WinUSB 컨트롤러가 없을 때 `A2854.Probe 를 무한 재실행하는 것은 정보가 없다. **내장 AX200을 WinUSB로 교체하지 말 것**(일반 Bluetooth 끊김 위험).

## 4. 외부 프로젝트 조사와 포크 결정을 내린 이유

원본 [AnthoDingo/AppleRemoteWin](https://github.com/AnthoDingo/AppleRemoteWin)은 1세대 Siri Remote A1513/A1962용 AGPL-3.0-or-later WPF/.NET 10 앱. README의 구형 `no kernel driver / hardware not tested 류 문구보다 개발자 `CLAUDE.md(10/15 갱신)와 PR/커밋이 최신이다.

- `src/AppleRemote.Core/Hci.cs, `Ble.cs, `Smp.cs, `Gatt.cs: Windows 기본 Bluetooth 스택을 건너뛰고 WinUSB USB 동글에 대해 직접 HCI/L2CAP/ATT/페어링 구현. `UsbHci.cs 와 `SiriRemoteBle.cs 가 이를 사용한다.
- [PR #15](https://github.com/AnthoDingo/AppleRemoteWin/pull/15): Realtek TP-Link UB500 (`2357:0604) WinUSB 경로, firmware patch/extended LE scan/connect, 1세대 원격 재연결 실기기 성공 보고. 최초 앱 페어링 등 일부는 미검증. Qualcomm QCA61x4A도 개발 기록에 실기기 성공 보고.
- [Jack-R1/SiriRemoteDriver](https://github.com/Jack-R1/SiriRemoteDriver) 및 [AnthoDingo/AppleRemoteWin-Driver](https://github.com/AnthoDingo/AppleRemoteWin-Driver): KMDF 필터로 ATT 핸들을 바꿔 접근 가능한 Battery GATT를 통해 HID 데이터 전달하는 **구형 리모컨 전용** 연구. A2854에 기존 고정 핸들을 그대로 쓰면 안 됨.
- [Driver 이슈 #1](https://github.com/AnthoDingo/AppleRemoteWin-Driver/issues/1): 해당 Rust 드라이버 설치 경로는 Qualcomm QCA61x4A 중심이며 **Intel `ibtusb/BTHUSB와 다른 스택은 검증 대상**. 실제 호스트에 시험서명/보안 부팅 변경/커널 필터 무작정 설치 금지.
- [AnthoDingo ESP32-S3 dongle](https://github.com/AnthoDingo/AppleRemoteWin-Dongle), [Jakkumn/SiriRemoteESP](https://github.com/Jakkumn/SiriRemoteESP), [mobe-dev/ESP32 receiver](https://github.com/mobe-dev/esp32-siri-remote-receiver), [SiriRemoteForge (macOS A2854)](https://github.com/HOLODATA-COM/SiriRemoteForge): 대안/타 기기 연구 자료. 일부 프로젝트에서 A2854 실사용 보고가 있으나 Windows Intel AX200의 직접 접근 성공 증거는 아님.
- **전략:** 별도 첫 세대 전용 프로젝트와 싸우지 말고 **사용자가 포크한 AppleRemoteWin에서 A2854 독립 기능 브랜치 개발**. 직접 수신 통신 계층을 재활용하고 Linux A2854 디코더 실측 fixture 이식. 완성·실측 확인되면 upstream PR을 고려한다. 기존 Linux 실험 저장소는 삭제/아카이브하지 않는다.
