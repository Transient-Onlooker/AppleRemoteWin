# Siri Remote A2854 / AppleRemoteWin 포크 — 2026-10-18 인수인계 연결 문서

> **최신 상태 (2026-10-21):** 현재 개발 기준은 [AppleRemoteWin 최신 인수인계](https://github.com/Transient-Onlooker/AppleRemoteWin/blob/feat/a2854-support/docs/HANDOFF_2026-10-21_A2854.md)다. 내장 AX200의 Siri Remote HID Code 10 장치를 관리자 권한으로 **1회 재시작했으나 실패**(계속 `0xC00000B9`). 별도 WinUSB Bluetooth 동글 경로로 전환 준비 중이며, T490s(사용자 확인 Intel AC 9560)는 아직 실험 전. 최신 A2854 BLE 주소 유형 보완 코드는 GitHub에 반영됐지만 **수정 후 실제 Windows 빌드/테스트와 입력 수신 성공은 미확인**. 아래 10/18의 미실행 표기는 당시 역사적 기록이다.

> **현재 주 작업 저장소가 변경됐다.** 기존 `siri-remote-for-windows` 는 Linux/WSL2 실험 원본, A2854 디코더·패킷 증거와 Windows HID 원인 분석 기록을 보존한다. 새로운 Windows 네이티브 실험·C# 코드 개발은 **`Transient-Onlooker/AppleRemoteWin`의 `feat/a2854-support` 브랜치**에서 계속한다. 이 파일은 역사적 기록과 최신 작업을 연결하기 위한 인덱스이며, 기존 `HANDOFF_2026-10-17.md` 문서를 삭제하거나 현재 상태로 오인하지 않는다.

## 현재 핵심 사실 (2026-10-18)

| 구분 | 상태 |
| --- | --- |
| Linux/WSL2 + BlueZ + Intel AX200 + 물리 Siri Remote A2854 | **실제 버튼 `0xFB`·터치 `0xFC` 알림 수신 성공** |
| Windows WinRT GATT | `0x1812` 포함 7 서비스 확인, HID 특성 열거 `ACCESS_DENIED` |
| Windows 네이티브 HID 하위 장치 | 대상 Siri Remote HIDClass/`mshidumdf`, Code 10, `0xC00000B9` |
| Windows Intel AX200 드라이버 | `BTHUSB` / `oem116.inf` / 정상 상태; `usbipd Not shared` |
| 새로운 포크의 C# A2854 디코더·콘솔 | 구현·커밋됨. **.NET SDK 10.0.402, 89/89 테스트 통과, Windows Probe Release 빌드 성공** |
| 실제 A2854 수신을 위한 Windows Probe | 별도 WinUSB Bluetooth 컨트롤러가 없어 `WinUSB controller unavailable`; **BLE 연결 자체는 시작하지 못함** |
| 마지막 내장 Bluetooth 실험 | 포크의 `tools/A2854.Probe/LastBuiltinHidAttempt.ps1` 커밋됨; **아직 물리 장치에서 실행했다고 확인되지 않음** |
| 사용자 결정 | 제한적인 내장 `BTHUSB` HID Code-10 마지막 시도 → 실패 시 외장 USB Bluetooth 동글 구매·WinUSB 직접 HCI 실험 |

## 다음 담당자가 해야 할 첫 작업

1. **AppleRemoteWin 포크의 [최신 통합 인수인계](https://github.com/Transient-Onlooker/AppleRemoteWin/blob/feat/a2854-support/docs/HANDOFF_2026-10-18_A2854.md)를 먼저 읽고 그 브랜치에서 계속할 것.**
2. 사용자의 실제 Windows PowerShell 결과를 받으며 `LastBuiltinHidAttempt.ps1` 의 **읽기 전용 preflight**를 먼저 확인. 유일한 Siri Remote HIDClass Code 10 대상이 확인되지 않으면 관리자 `-Restart`를 실행하지 않는다. 문서가 코드를 커밋했다는 것은 실제로 실행했다는 뜻이 아니다.
3. 조건을 만족하고 사용자가 승인한 경우에만 대상 HID child `pnputil /restart-device` **1회** 후 성공 여부 판정. **AX200 드라이버를 WinUSB로 교체하거나 시험서명을 켜지 말 것.**
4. 실패하면 별도 USB Bluetooth 동글(예: 원본 프로젝트의 1세대 시험 기기 TP-Link UB500; **A2854 검증 전**)을 준비해 C# 콘솔 직접 HCI 접근을 검증. WPF 앱 완성·A2854 실수신 성공은 아직 아님.

**개인정보:** BLE 주소, 일련번호, 원본 ETL, 페어링 키, Windows 고유 장치 경로를 GitHub에 기록하지 않는다. 두 저장소의 GPL-3.0 / AGPL-3.0-or-later 고지도 유지한다.
